# Story 3.1 Persistence, Settings, and Accessibility Polish
Status: Approved
Epic: 3 — Persistence, Settings, and Accessibility Polish

As a returning player,
I want my stats and preferences saved on my device,
so that the app remembers my progress and comfort settings across sessions.

## Acceptance Criteria
1. Stats are tracked by mode (Solo, Pass‑and‑Play): wins/losses/draws update correctly after each match.
2. Stats persist across restarts using device‑local storage; a Reset Stats action clears them.
3. Settings screen includes toggles for sound and haptics; changing a toggle updates behavior immediately and persists.
4. Basic sounds (move click, win jingle) and light haptics (move, end‑state) are used when enabled.
5. Accessibility polish: confirm AA contrast, min 44dp touch targets, sensible focus order, and respect system Reduced Motion.
6. Integration tests cover settings toggles (persist and apply) and a simple stats update flow.

## Tasks / Subtasks
A. Storage Wrapper
- Implement `mobile/src/services/storage/` with typed API:
  - `getStats()`, `saveStats()`, `getSettings()`, `saveSettings()`, `resetAll()`
  - Use AsyncStorage with stable keys: `xo:stats:{mode}`, `xo:settings`
  - Handle read errors with safe defaults; ensure atomic update pattern
  - References: Components; Data persistence [Source: architecture/components.md#3.-components] [Source: architecture/data-persistence.md#5.-data-and-persistence]

B. Settings Screen + Toggles
- Add `Settings` screen; wire toggles to storage; apply immediately in UI
- References: Components/screens; Tech stack (haptics/sound) [Source: architecture/components.md#3.-components] [Source: architecture/tech-stack.md#2.-tech-stack-definitive]

C. Sounds & Haptics
- Integrate `expo-av` for click + win jingle, and `expo-haptics` for light feedback (respect toggles and Reduced Motion)
- References: Tech stack; A11y standards [Source: architecture/tech-stack.md#2.-tech-stack-definitive] [Source: architecture/accessibility-ux.md#6.-accessibility--ux-standards]

D. Game Flow Integration for Stats
- Update stats at end‑state; ensure correct mode attribution
- References: Workflow sequence [Source: architecture/core-workflows.md#4.-core-workflows]

E. Integration Tests
- Verify toggles persist and apply; play a match and verify stats saved and loaded after app restart
- References: Testing strategy [Source: architecture/testing-strategy.md#8.-testing-strategy]

## Dependencies
- Story 1.1 completed (base UI/engine)
- Story 2.1 completed (if verifying Solo stats in tests)

## Risks / Mitigations
- Risk: AsyncStorage read/write failures → use defaults; surface non‑blocking error state minimally.

## Rollback Plan
- If stability issues occur, disable sounds/haptics while preserving storage and settings UI; or temporarily gate persistence while investigating.
