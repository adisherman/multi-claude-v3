# Story 1.1 Core Game Engine & UI (Pass-and-Play)
Status: Approved
Epic: 1 — Core Game Engine & UI

As a player,
I want to play a complete local pass‑and‑play tic‑tac‑toe match,
so that I can enjoy a quick, offline game with a friend on one device.

## Acceptance Criteria
1. From Home, I can start a Pass‑and‑Play match in ≤3 taps.
2. A 3×3 board renders with empty cells; tapping an empty cell places the current player’s mark and disables that cell.
3. Turn indicator clearly shows whose turn it is and updates after each valid move.
4. Overwrites are prevented; tapping an occupied cell has no effect (or provides subtle feedback).
5. Win/draw detection is correct for all lines and states; the winning line is visibly highlighted.
6. End‑state dialog offers Rematch and Back to Home; Rematch restarts instantly on the Game screen.
7. Basic polish: subtle tile reveal and win‑line animation; target 60fps during play.
8. Accessibility: touch targets ≥ 44dp; sufficient contrast for marks/controls; sensible focus order where applicable.
9. Offline‑first: no network calls; game is playable with no connectivity.
10. Integration tests pass for the full Pass‑and‑Play happy path (Home → Game → Win/Draw → Rematch).

## Tasks / Subtasks
A. Game Engine (Core)
- Implement pure TS engine in `mobile/src/core/engine/` with:
  - `createGame()` → initial state
  - `applyMove(state, cell, player)` → next state with validation
  - `getWinner(state)` and `isDraw(state)` → detection
  - Types for `Board`, `CellIndex`, `Player`, `GameState`
  - Unit tests for all win/draw paths and illegal moves
  - References: Engine responsibilities [Source: architecture/components.md#3.-components]; Testing scope [Source: architecture/testing-strategy.md#8.-testing-strategy]

B. UI Components
- `Board`, `Cell`, `HUD` components in `mobile/src/ui/components/`
  - Large touch targets, high‑contrast marks [Source: architecture/accessibility-ux.md#6.-accessibility--ux-standards]
  - Subtle tile reveal and win‑line animation; memoize where appropriate [Source: architecture/performance-reliability.md#7.-performance--reliability]
- References: Components list [Source: architecture/components.md#3.-components]

C. Screens and Navigation
- Minimal stack navigator in `mobile/src/navigation/`
- `Home` screen: Pass‑and‑Play CTA; quick actions
- `Game` screen: Board + HUD; end‑state dialog (Rematch, Back)
- References: Screens list [Source: architecture/components.md#3.-components]; Source Tree [Source: architecture/source-tree.md#9.-source-tree-authoritative-guide]

D. Integration Tests (RN Testing Library)
- Happy path: start Pass‑and‑Play → play to win and draw → verify win line and dialog → Rematch
- References: Testing strategy [Source: architecture/testing-strategy.md#8.-testing-strategy]

E. Accessibility & Performance Pass
- Verify 44dp targets, contrast, focus order; confirm 60fps during typical play
- References: A11y [Source: architecture/accessibility-ux.md#6.-accessibility--ux-standards]; Performance [Source: architecture/performance-reliability.md#7.-performance--reliability]
